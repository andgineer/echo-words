Настройка

echo-words настраивается в двух местах: TOML-таблица исходных языков и переменные окружения для всего остального.

Исходные языки

languages.toml — источник истины для языков, слова которых вы разбираете. Файл лежит в ECHOWORDS_DATA_DIR и переезжает вместе с ним; путь можно переопределить через ECHOWORDS_LANGUAGES_CONFIG. Добавление языка — это изменение настроек, а не кода.

[languages.en]
name       = "English"
deck       = "EchoWords: English"
dict_api   = "en"              # код dictionaryapi.dev; опустите, если языка там нет
tts        = "piper"           # piper | edge
tts_voice  = "en_US-lessac-medium"
accent     = "us"              # имеет смысл для английского
script     = "latin"           # latin | cyrillic | latin+cyrillic

[languages.sr]
name           = "Српски"
deck           = "EchoWords: Serbian"
tts            = "edge"
edge_tts_voice = "sr-RS-SophieNeural"
script         = "latin+cyrillic"
prompt_hints   = "for nouns give gender and plural, for verbs give aspect"

Каждая запись задаёт отображаемое имя, собственную колоду Anki (deck), допустимую письменность ввода (script), код словаря, если он есть, а также движок и голос произношения. В репозитории лежит languages.example.toml с готовыми записями для английского, немецкого и сербского.

Note

Сербский намеренно озвучивается кириллицей: голоса sr-RS неправильно произносят латинское написание.

Переменные окружения

Все переменные начинаются с ECHOWORDS_. Закоммиченный .deploy.example/.env документирует каждую; ниже те, что меняют чаще всего.

Переменная Значение По умолчанию
ECHOWORDS_DATA_DIR коллекция Anki, модели голосов, состояние брокера, кэш аудио — своей базы данных нет ~/.echo-words
ECHOWORDS_TARGET_LANG язык, на котором пишутся все объяснения и переводы ru
ECHOWORDS_LANGUAGES_CONFIG путь к таблице языков <data dir>/languages.toml
ECHOWORDS_LLMBROKER_HOME где llmbroker хранит свой список моделей и журнал вызовов <data dir>/llmbroker
ECHOWORDS_API_MODEL алиас платной модели, на которую переключается каскад; пустое значение полностью отключает платные вызовы gpt-fast
ECHOWORDS_API_DAILY_CAP платных вызовов в сутки, 0 — без ограничения 100
ECHOWORDS_ANKI_SYNC синхронизировать коллекцию с AnkiWeb после добавления true
ECHOWORDS_ANKIWEB_USER / _PASSWORD учётные данные AnkiWeb обязательны при включённой синхронизации
ECHOWORDS_SYNC_ENDPOINT свой сервер синхронизации Anki вместо AnkiWeb пусто
ECHOWORDS_ACCENT us или uk для английского аудио us
ECHOWORDS_AUDIO_TIMEOUT сколько секунд ждать произношение, прежде чем отправить без него 20
ECHOWORDS_HOST / ECHOWORDS_PORT адрес привязки; оставьте на loopback, входной дверью служит Tailscale 127.0.0.1:8080

Язык интерфейса переменной окружения не является. Это выбор для конкретного устройства, который делается в шапке (EN/RU) и запоминается в браузере. Он не меняет ECHOWORDS_TARGET_LANG — язык, на котором написаны ваши карточки.

Ключи LLM-провайдеров

Бесплатному пулу нужен хотя бы один из GROQ_API_KEY, OPENROUTER_API_KEY, GEMINI_API_KEY, ZAI_API_KEY; все четыре дают пулу полный набор для переключения при отказе. Команда python -m llmbroker env freetier печатает актуальный список для установленной версии llmbroker вместе со ссылками на регистрацию.

Платному запасному варианту по умолчанию (ECHOWORDS_API_MODEL=gpt-fast) дополнительно нужен OPENAI_API_KEY. Укажите ECHOWORDS_API_MODEL=, чтобы работать только на бесплатном пуле.

AnkiWeb

Задайте ECHOWORDS_ANKIWEB_USER и ECHOWORDS_ANKIWEB_PASSWORD и оставьте ECHOWORDS_ANKI_SYNC=true. При первом запуске headless-коллекция полностью скачивает существующую коллекцию аккаунта, прежде чем добавить хоть одну локальную карточку. Пароль используется один раз — для получения ключа синхронизации, который затем хранится в ECHOWORDS_DATA_DIR и переиспользуется.

Оставьте исходящий HTTPS открытым для *.ankiweb.net: AnkiWeb перенаправляет синхронизацию на пронумерованные шарды, поэтому разрешение только sync.ankiweb.net будет периодически ломаться.

Свой сервер синхронизации Anki выбирается через ECHOWORDS_SYNC_ENDPOINT.
